# Codex 连接评分

## 先看任务状态，再看公共连接

顶部采用像素爱心和常驻的 13px 连接分数，显示 0–100，采样不足或过期时显示「—」。爱心与数字颜色表达公共连接分档；独立小圆点表达当前任务提醒（等待、静默、错误或状态待确认），高连接分保留该提醒。点击徽章从当前位置展开任务状态和公共连接详情。

Monkex 的主运行状态来自当前任务的结构化活动证据，通过 `operational` 返回文字状态与等级。该对象没有整体健康百分比。独立的连接分通过 `score` 返回，固定标注 `metric=public_connection`、`unit=points`、`authenticated=false` 和 `scope=public_path`，界面使用“公共连接质量”名称。

| 当前证据 | 主状态 |
|---|---|
| 当前回合明确失败，且结构化错误发生在最近 300 秒内 | 最近回合失败 · 异常；明确的连接错误与一般任务错误分别说明 |
| 只有本轮启动事件，尚未观察到后续响应 | 等待响应 · 提醒 |
| 有近期思考、回答或工具事件 | 近期有活动 |
| 有未结束工具调用，且有近期事件 | 等待工具返回；保留工具状态 |
| 任一任务至少 180 秒没有新活动 | 无新活动 · 提醒；工具调用仍未结束时说明等待工具返回 |
| 本地同步超过 30 秒、观察器读取失败或部分任务证据缺失 | 状态待确认 |
| 没有运行任务且同步新鲜 | 空闲 |

未结束的工具调用只能证明尚未观察到返回；它不能证明工具进程持续工作。长时间思考和工具等待保留原因未知，公共请求可达也不能消除该提示。部分任务有活动时，其余静默或未知任务仍保持提醒；`assessment` 同时保留这个优先级，公共路径风险与官方公告留在详情。

`recent_issues` 单独列出当前回合的近期终态失败，不混入运行速度统计。错误必须具有与卡片 `latest_turn_id` 一致的 `turn_id`，发生时间位于当前时间之前的 300 秒以内，且任务已明确标记失败。新回合、旧回合错误、未来时间和同步过期均不会沿用旧失败状态。`http_connection_failed` 表示该回合报告了连接错误；其他结构化类型统一为 `task_error`，保留一般任务失败语义。采集不解析或保存错误消息正文，也不把 MCP 工具连接错误、历史应用日志或公共探针失败冒充当前生成流断开。

临时同步丢失时，原运行卡以 `status=unknown`、`last_observed_status=running`、`sync_pending=true` 保留；诊断 `tasks` 与兼容字段 `running_tasks` 包含这些待确认卡，`operational.unknown_tasks` 明确计数，旧 Token 速度隐藏。观察恢复后再按新证据更新状态。

任务的 `token_signal` 解释用量显示：`usage_reported` 有新增报告，`no_recent_usage_report` 最近一分钟没有用量报告，`tool_wait` 正等待工具，`thinking` 最近一次事件为思考，`awaiting_report` 样本尚不足，`report_idle` 已有样本但当前窗口为零，`sync_unavailable` 当前观察不可用。Token 报告按批次到达，`0/min` 不证明模型停转或网络故障。

Monkex 将近期小型公开 HTTPS 探针汇总为 **0–100 分的启发式连接评分**。100 分表示这段样本中的指定公共路径响应稳定，0 分表示样本已足够且连接表现很差。分数适用于当前系统代理、VPN 或直连路径，衡量的范围始终是 **public_path**。

评分与任务活动分开展示。当前 Codex 任务有新活动时，`codex_observed` 为 `true`；任务长时间无事件、token 用量暂未上报、正在运行工具或本地任务同步过期，都保持独立提示。它们不扣连接分。公共路径评分不能证明真实生成请求的速度、VPN 本身的质量或故障责任方，也不是未来可用率的概率。

无凭据的 HEAD 探针只验证特定公共入口能否返回预期 HTTP 响应。登录会话有效性、真实生成流、模型排队和重连成功均需要实际运行证据。探针采用 Monkex 进程的系统/环境代理；Codex 的真实流量路径和当前探针路径是否一致保持未验证。官方公告和短时抽样属于排查参考，不能替代个人会话状态。

## 数据与样本

评分使用最近 15 分钟内的三项服务观察：Codex 公共入口、OpenAI API 入口、登录服务入口。采集端负责为各固定入口识别预期响应。例如，不携带凭据的 Codex 入口返回预期的 401/405、API 入口返回预期的 401，均可作为有效响应；登录公开配置入口预期 200。评分模块只读取已分类的布尔字段，不发送请求。

- 每项服务至少有 3 个独立轮次样本，才显示临时分数。
- 每项服务至少 6 个独立轮次，且样本跨度达到 15 秒，标记为短时检查结果。它仍只描述该短时样本。
- 缺失的登录服务等记录为未知，保持收集中；采集失败产生的明确失败记录计入评分。
- 最新样本超过 180 秒，数值变为未知并标记过期。缺失、过期和真实的 0 分分别表示。
- 同一 `round_id`、同一服务只计一次，采用最早观察；重试使用新轮次。无效字段和未来时间记录不计入。

## 计算公式

服务权重为 Codex 0.60、API 0.25、登录服务 0.15。对每个分项，先算各服务的质量值 `q`（0–1），再使用：

```text
合并质量 = 0.60 × 加权平均(q) + 0.40 × 最低服务质量(q)
原始分 = 60 × 响应可靠性 + 25 × 延迟质量 + 15 × 稳定性
最终分 = round(原始分)，再应用下列分数上限
```

每项服务的响应可靠性是该服务的预期响应次数除以尝试次数，再按上述公式合并为可靠性分。预期响应必须同时具有 `transport_ok=true` 和 `expected_response=true`。403/429 保留为“传输可达、响应受限”，不算预期成功；其 HTTP 响应耗时仍是真实延迟。

页面“连接成功”使用实际成功总次数除以实际尝试总次数，即顶层 `success_percent`。例如三项服务共 60 次尝试、53 次预期响应，显示 88.3%。公式使用的加权质量单独放在 `weighted_success_percent`，用于解释可靠性得分。

延迟质量使用各服务的 P95：不超过 500ms 得 1；500–3000ms 线性降至 0.4；3000–6000ms 线性降至 0；超过 6000ms 得 0。分位数采用相邻样本线性插值。

稳定性依据 `P95−P50`：0ms 得 1，1500ms 及以上得 0，中间线性计算。断连或超时在**评分延迟样本**中至少按 6000ms 计入，防止只统计成功响应而隐藏失败。该保守下限不冒充实测耗时。失败下限也不能抬高 P50 来制造稳定性恢复：评分的 P50 采用评分样本中位数与传输可达样本中位数的较小值；全部不可达时稳定性为 0。

顶层 `p50_ms`、`p95_ms`、`jitter_ms` 保留实际测得的耗时统计。每个服务另提供 `scoring_p95_ms`，区分保守计分依据。成功响应缺少耗时，保持未知分数并提示测量不完整。

## 分数上限与官方公告

| 已有证据 | 分数上限 |
|---|---:|
| 任一必需服务的预期响应率低于 90% | 69 |
| 任一必需服务的预期响应率低于 70% | 39 |
| Codex 最近连续 3 次均非预期响应，且并非全部为 403/429 | 30 |
| Codex 最近 3 次存在 403/429 受限响应 | 69 |
| 新鲜官方状态明确将 Codex 组件标为性能下降或维护 | 70 |
| 新鲜官方状态明确将 Codex 组件标为部分或严重中断 | 40 |

多个上限同时适用时取最小值。官方状态优先采用明确的 Codex Desktop 组件；例如 Desktop 正常时，Codex Web/API 的中断只作独立提示。状态页没有明确 Desktop 组件时，才使用名称为 Codex 的通用组件作为回退。未知或过期官方状态保持未知；只有 Responses、其他服务的异常或未明确关联目标组件的公告，作为独立提示展示，不压低分数。分数上限描述风险信号，不构成对单个慢任务原因的认定。

例如，Codex 入口 30 次有 26 次成功，即使成功请求很快，也受 69 分上限约束；30/30 次成功且三项服务均快速稳定的样本可达到 100 分。页面下载带宽不进入计算。

## 返回接口

纯函数：`score_runtime_health(history, *, now, runtime=None, official=None)`。

主要字段包括 `value`（整数或 null）、`grade`（good/fair/poor/collecting/stale）、`confidence`（collecting/provisional/short_check）、样本及轮次数、预期响应百分比、延迟分位数，以及 `components` 内的可靠性 0–60 分、延迟 0–25 分、稳定性 0–15 分。正常等级阈值为 85 分，关注等级阈值为 60 分。

`notes`、`caps`、各项 `services` 和 `method_version=public-path-v1` 支持解释得分。评分函数无文件访问、无网络请求、无持久化历史；只消耗调用方提供的时间、轮次、服务代号、状态、耗时和公开状态元数据。
